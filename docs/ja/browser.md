# ブラウザ統合

[English](../browser.md) · [リリースと検証](release.md)

## 責務

| 配置             | 内容                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| `src/generated/` | 固定したWASM ABIの生成バインディング                                         |
| `src/worker/`    | Workerの通信、マニフェストとバイト列の検証、クエリ変換、索引のライフサイクル |
| `src/view/`      | 編集可能なコンボボックス、入力断片の選択、候補の挿入                         |
| `tools/data/`    | 検証済みのCommon Crawl語彙と索引をビルド時に準備                             |
| `tests/`         | ブラウザE2E、キー・タッチ操作、古い応答、障害を注入するテスト                |

miseで固定したTypeScript、Vite、pnpm、Biome、Playwrightを使います。デモは[Common Crawlの語彙](commoncrawl.md)で補完を試せる独立したページです。候補を選ぶと入力欄に挿入します。アプリケーションは、補完後のクエリを自身の検索サービスに送信できます。索引の準備工程が辞書、品詞の選択、コーパス上の頻度、使用する固定の順位重みを担当します。Workerは成果物を読み込み、生成された整数の重みを使います。[コーパス仕様](https://github.com/tkhshtsh0917/nemesia/blob/main/docs/ja/corpus.md)。

## 入力時の補完

エンジンは候補キーの接頭辞に対して補完します。日本語デモでは、抽出した語を一語ずつ提示します。入力断片が一つなら入力全体を使います。Unicode空白で区切られた複数語があり、キャレットが末尾なら、最後の断片だけを補完し、その前は元のまま残します。補完対象の断片が空なら候補一覧を閉じます。IME変換外では、選択範囲があるか、キャレットが入力途中にあると候補一覧を閉じます。キャレットを末尾に戻すと補完を再開します。変換中は選択範囲が最後の単語内にある場合も、その単語の補完候補を表示できます。スペースを含まない日本語入力は一つの断片として扱います。ホストは断片の選び方を変更したり、同じコアAPIでフレーズ候補を使ったりできます。

例えば `日本史 せか` という入力に対し、`世界` が読み `せかい` で索引されていれば `日本史 世界` を提示できます。元の断片と、該当する場合は上限付きのかな・英字変種1件を送ります。元の断片が一致しても変種の照合を続けます。Workerは両方の照合と順位付けを、一つのWASMリクエストとして委ねます。

リストボックスを開く編集可能なコンボボックスを使い、候補を自動では選択しません。DOMのフォーカスは入力に残します。矢印キーでアクティブな候補を移動し、Escapeで閉じ、候補がアクティブな状態でEnterを押すと挿入します。アプリケーションに組み込む場合は、アクティブな候補がない状態でのEnterで入力をホストに送信できます。独立したデモでは補完後の入力欄に値を残します。ポインターで選択しても候補を挿入します。アプリケーションに組み込む場合は、独立した送信操作を提供します。Tabは通常のフォーカス順を維持し、テキスト編集キーはブラウザに任せます。IMEの変換中も候補を表示しますが、候補の確定と送信は変換が完了するまで待ちます。IMEの変換を確定したEnterで候補の選択や送信も実行することはありません。すべての文字列はテキストノードとして描画します。準備完了、候補なし、エラーをライブ領域で通知し、候補ごとの読み上げは要求しません。[WAI-ARIAのコンボボックスパターン](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) · [W3C UI Eventsの変換イベント](https://www.w3.org/TR/uievents/#events-compositionevents)。

## スケジューリングと回復

リクエストには単調に増加するID、Workerインスタンスの識別情報、現行の索引世代を持たせます。変換イベントを含め、入力、選択の状態、世代が変わったら古いIDを無効にします。照合中のリクエストを1件、待機中を最大1件とし、待機中は最新の入力で差し替えます。Workerの応答を受け入れる前と、DOMに反映する直前に新しさを確認します。クリックやキー操作で表示済みの候補を適用する直前にも、入力値と断片が現行のものと一致していることを確認します。

クエリが失敗したらそのクエリの候補を消し、索引は保持して次のクエリを受け付けます。停止したWorkerは取り替えられます。ホストが同じWorkerに差し替え索引を読み込ませた場合、失敗やサイズ超過でも現行世代を維持します。デモは起動時に読み込み、読み込みやWorkerの失敗時に再起動を案内します。切断・破棄の際はリクエスト、リスナー、古い結果を残しません。ブラウザでの形態素解析と補完入力のログ収集は設計の対象外です。
